# squad-programming 使用说明（给用户）

Agent 侧的完整流程见 `SKILL.md`。这份只讲你怎么用。

## 怎么触发

| 方式 | 例子 |
|---|---|
| 手动点名 | `/skill squad-programming` |
| 触发语 | 「把 XX 拆开同时做」「并行开发」「组队编程」「多开几个 agent 一起干」 |
| 直接派活 | 「重构 A 模块和 B 模块，并行做」 |

触发后**你不需要准备**任务包 —— 父 agent 负责拆解、生成验收标准、分配模型，你只给目标和方向。

## 触发后会发生什么

```
你下需求
  ↓
① 父 agent 拆解（MECE：子任务文件范围不重叠；顺序依赖合并不硬拆；子任务名必须**语义化**：`T<n> · <任务目的>`，不能裸 T1/T2）
  ↓
② 集结：父 workspace 改名任务包名 → 按任务名建 worktree（herdr，Spaces 树节点）→ worker 挂节点 pane 启动
  ↓
③ 准备检查：确认每个 pane 的 omp 已上线；每个子 omp 读任务包 + 核对模型可用，全部报 STARTED 才开工
  ↓
④ 并行干活：子 omp 求助会直接问父 agent，状态自动汇报
  ↓
⑤ 回收：每个子任务跑验收（测试/lint）→ 父把 branch + diff 摘要交接给你，**合并由你手动做**；你表态后父逐 pane/分支清理
```

## 你要做的

1. **给目标**（一句话需求即可）
2. **给验收标准**（想得到就给：「跑通全部测试」「保持接口兼容」；想不到**什么都不用给** —— 走 report-only，完成后把结果摆给你）
3. **合并**（最后一步）：skill 不碰 merge —— 你看摘要说「过」，自己去 `git merge <branch>`（或打回/丢弃）

## 成本

- 子 omp 默认用便宜档模型（deepseek-v4-flash / v4-pro），**不用 Claude**（被禁用清单拦住，除非你显式放行）
- 每个子任务可带 token 预算，超预算强制上报

## 注意事项

- **第一次用**：挑只读任务（调研、竞品分析）试链路，零副作用。熟了再上代码并行
- **拆不动会告诉你**：任务没法拆成无冲突的子任务时，父 agent 会直接说「不适合并行」，单 agent 做，不硬拆
- **安全护栏**：验收标准推导不出的任务走 report-only，父只整理结果不动代码；任何分支的合并、删除都等你表态 —— 你不在场也不会有意外干活
- **并行上限**：默认最多 3 个子 omp 同时跑（保护 CPU/磁盘），可调
- **集结后先等准备检查**：每个子 omp 会先报 `[T<n>] STARTED`（确认已读任务包、模型可用），全绿才开工；任何子任务没起来会当场失败并给你诊断
- 过程中你随时可以打断：通过父 agent 追加要求、调整方向

## 一个典型对话

你：`帮我并行做三件事：① 修 search 工具的超时 bug ② 补 read 工具的边界测试 ③ 调研一下 ast-grep 的替代品。用 squad 模式。`

父 agent（Phase 0 拆解后）：`拆成 3 个子任务，T1=T2 同一 worktree（都是 tools/ 目录，顺序接力），T3 只读并行。检查命令：bun test …。可以开始？`

你：`过`

之后等汇报，最后验收。
