# 上游能力移植的完成定义与范围边界

2026-09-16 决定：把上游（`can1357/oh-my-pi`）工具侧的能力差移植进本地时，一条能力算"做完"包含四项——能力、针对性测试、必要 prompt（`.md`）、CHANGELOG 条目——外加上游对应的 TUI 渲染；依赖按上游引入，不为单 binary 体积设限；范围以"只需本机已有件"为界，需要外部账号或云服务的不做；交付分波，先发一批文件面互不重叠、无前置的，验收后再拆剩余。允许改已有核心路径，但外部行为必须兼容（旧输入按旧语义），且无测试护栏的地方先补护栏再动。

**被否**：① 只做加法、核心路径一行不动——会砍掉约 5 条，且本地本就有测试护栏；② 不引任何新依赖——只卡住一项（tree-sitter 的结构化摘要）；③ 13 条一次全发——"TUI 渲染跟搬"是本次新定的验收口径，先用一小批校准。

**后果**：每个移植票都要带渲染验收面（快照测试或等价物）；票里点名的依赖必须同时说明为何不能复用本地已有件；"上游有但本地没有"不再自动等于"要移植"，先判它有没有消费者。
