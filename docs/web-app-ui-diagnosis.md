# Web App 全站 UI 诊断

> 诊断时间：2026-09-19
>
> 诊断范围：`packages/web-app` 当前运行中的 Web App、路由注册、页面组件与共享样式。
>
> 本轮仅诊断，不包含源码修改。

## 结论

当前问题不是单个首页的颜色或圆角问题，而是整个 Web App 都采用了“后台控制台堆信息”的设计方式：功能很多，但缺少统一的任务层级。

更严重的是，会话工作台当前存在运行时错误，核心页面实际不可用。

## P0：会话工作台运行时错误

访问 `#/workspace` 时出现：

```text
Unexpected Application Error!
ReferenceError: source is not defined
at SessionSidebar
```

相关位置：

- `packages/web-app/src/pages/workspace/SessionSidebar.tsx:175`
- `packages/web-app/src/pages/workspace/SessionSidebar.tsx:200`
- `packages/web-app/src/pages/workspace/SessionSidebar.tsx:204`

`SessionSidebar` 使用了 `source` 和 `setSource`，但当前组件没有定义对应状态。

这是功能故障，不是视觉问题。应优先修复，再进行工作台视觉改版。

## 全站共性问题

### 1. 页面展示事实多，行动引导少

多个页面直接展示：

- agentDir
- 会话根目录
- Project registry
- session ID
- protocol version
- gateway PID
- provider
- source
- scope
- 目录状态
- 连接 ID

这些信息对调试有价值，但不应全部进入第一视觉。当前产品更像“把后端返回的数据完整摊在页面上”，而不是“先告诉用户该做什么，再按需展开系统细节”。

### 2. 容器规则过于简单

当前主要使用：

```css
.page-narrow: max-width: 760px
.page-wide: max-width: 1100px
```

并在多个页面重复使用：

```tsx
px-10 pt-8 pb-12
```

问题：

- 首页 760px 在大屏下过窄
- 设置页的窄容器不适合复杂表单
- 模型、用量、Agent 页面在宽容器里承载了过多内容
- 工作台是多栏布局，却和普通页面共用普通页面的外壳思路

容器应按页面任务区分：对话型、列表型、配置型、数据型、工作区型。

### 3. 过度依赖边框、卡片和浅灰背景

全站大量使用 `border-hairline`、`bg-surface`、`bg-surface-2`、`rounded-lg`、`rounded-xl`。

结果是每块内容都像独立卡片，但重要区和次要区没有明显权重差异。页面看起来很满，却不容易判断重点。

### 4. 响应式断点不统一

`AppShell` 主要以 `md` 控制主导航，而 `SessionSidebar` 使用 `lg` 控制工作台侧栏。窄窗口下可能出现主导航已切换为移动模式，但工作台侧栏仍按另一套规则工作的情况。

应统一断点和多栏收缩策略。

## 分页面诊断

### 首页 `/`

问题：

- 欢迎页、聊天页、Agent 切换页、项目状态页、快捷入口页混在一起
- 主输入区不够突出
- 最近一轮对话占据过多视觉空间
- Agent 卡片和左侧导航重复
- Project 未声明状态形成大块空白
- 5 个快捷入口权重相同
- Agent、Project、工作区、会话 UUID 等技术上下文铺得过开

建议结构：

```text
当前 Agent 状态
主输入框
待处理事项
最近工作
```

### 会话工作台 `/workspace`

问题：

- 当前直接报 `source is not defined`
- 功能包含 SessionSidebar、FileExplorer、Transcript、ComposerBar、RightPanel、ChangesPanel、ArtifactsPanel、DiffView、FilePreviewPane，已经接近 IDE
- 左侧会话栏、文件栏、右侧面板同时存在时，主对话区域容易被压缩
- 多个侧栏可能同时占据固定宽度
- 移动端和桌面端断点不一致

建议：

```text
主区：对话与输入
左区：会话
右区：文件、变更、产物，按需打开
```

右栏不应默认和主区争夺空间。

### 会话记录 `/records`

实际页面显示 101 条会话，每行同时提供“回放 / 诊断 / 导出”。

问题：

- 长列表信息密度过高
- 状态、Agent、时间、消息数量和操作按钮挤在一起
- 会话列表和健康度大盘是两个不同任务，却放在一个页面
- 自动生成的会话、cron、测试会话混杂
- 诊断操作和普通回放操作权重相同

建议拆为：

1. 最近会话
2. 全部记录
3. 诊断分析

列表行只保留一个主操作，其余放入更多菜单。

### Agent 总览 `/agents`

这是全站相对清楚的页面之一，已有 workspace 筛选、状态筛选、搜索、gateway 状态、Agent 卡片和创建入口。

问题：

- Agent 管理和运行监控混在一起
- gateway PID、bridge、scheduler 与 Agent 卡片同级
- “创建员工”和 Agent 产品概念不完全一致
- Agent 卡片更像员工通讯录，而不是数字员工工作状态

建议卡片优先展示：

- 正在做什么
- 最近结果
- 待我确认
- 最后活跃时间

### Skills `/skills`

页面同时包含当前 Agent、路径、Project、Skill Hub、远程技能市场、Project 技能、全局技能、演化技能、指纹和更新时间。

实际页面出现远程市场错误：

```text
远程技能市场不可用：Server rejected "list_remote_skills"
```

问题：

- 本地技能管理和远程市场混在一起
- 磁盘技能、当前会话加载技能、演化技能是三种不同对象，却放在同一信息流
- 文件路径、指纹、更新时间占据太多内容
- 长描述直接平铺，页面滚动过长
- 远程错误成为主要视觉内容

建议拆为：

```text
已加载
可发现
技能市场
```

默认只展示技能名、状态和用途，路径、指纹、版本放进详情抽屉。

### Memory `/memory`

页面直接展示 Agent memory、Project memory、MEMORY.md、memory_summary.md、raw_memories.md、session memory、user.md 和 evolution 数据库。

问题：

- 系统内部存储结构直接暴露
- 用户看到的是 declared、canonical、raw、summary、JSONL、数据库，而不是记住了什么
- 大段 Markdown 直接平铺，体验像文件浏览器

建议以记忆内容为中心：

```text
用户偏好
Agent 事实
项目知识
最近变化
```

文件名和路径放入“查看来源”。

### Todo `/todo`

实际页面有 15 条未完成事项，每条都带编辑、延期、开始、取消、删除。

问题：

- 所有任务平铺
- 优先级、状态、来源、Project 视觉层级弱
- 每行操作过多
- 通用任务和 Agent 任务混在一起
- 没有突出今天真正需要处理的任务

建议默认分为：

```text
今天
进行中
等待确认
以后
```

每行只保留主操作，其余进入更多菜单。

### 模型 `/models`

模型中心包含模型目录、Providers、运行时配置。目录页又包含搜索、Provider、接入状态、thinking、vision、tools、输入模态和上下文长度筛选。

问题：

- 配置、目录浏览、Provider 管理混在同一入口
- 筛选条件过多
- 目录状态、缓存、回落等技术状态过于突出
- 普通用户难以快速完成模型选择

建议分为：

```text
当前使用
选择模型
Provider 配置
高级诊断
```

普通用户默认只看到前两层。

### 语音 `/voice`

源码显示该页同时承载基础语音、Jarvis、Listen、STT、TTS、声线、播报速度、自动播报、静默时间、唤醒词和多轮记录。

问题：

- 录音页和语音配置页混在一起
- 初始页面功能过多，用户不清楚当前是在录音还是配置

建议默认只保留：

```text
开始录音
实时转写
发送给当前 Agent
```

语音偏好放入设置抽屉。

### 定时任务 `/tasks`

页面同时包含创建表单、Agent / Project 绑定、任务列表、执行日志、试跑、启停、改绑和删除。

问题：

- 创建和管理两个任务混在长页面
- scope、状态、日志和试跑同时出现
- 不可执行任务需要展示原因，但当前容易形成错误信息堆积
- 调度表达式对普通用户不友好

建议：

```text
任务列表页
  └─ 新建任务抽屉
  └─ 执行日志抽屉
  └─ 任务详情页
```

### 用量 `/insights`

页面同时包含 KPI、趋势、模型成本、文件夹统计、Agent / Project / Session 范围、Session 统计以及 Learning / Memory 状态。

问题：

- 同时承担成本报表、请求量报表、Session 分析、Agent 分析和学习系统状态
- 用户很难快速判断页面主要解决什么问题
- 默认信息量过大

建议拆为：

```text
用量概览
成本与模型
Agent 效果
学习与记忆
```

### 设置 `/settings`

源码接近 900 行，包含连接、会话行为、主题、快捷键、工作目录、通知、钉钉、桌面版本、更新和危险操作。

问题：

- 页面过长
- 桌面壳设置和 Web 设置混在一起
- 连接配置和产品偏好没有明显区分
- 危险操作、更新和钉钉集成处于同一纵向页面

建议使用二级导航：

```text
连接
工作区
会话
通知
语音
桌面应用
高级
```

危险操作单独放入“高级”。

### Agent 详情、会话回放、诊断报告

相关路由：

```text
/agents/:id
/records/:id
/records/:sessionId/diagnosis
/records/dimension/:dim
/m
```

问题：

- 二级页面与一级页面共用同一套浅色卡片风格
- 详情、回放、诊断的层级差异不够明显
- 从列表进入详情后，返回路径和上下文需要加强

建议形成明确路径：

```text
列表 → 详情 → 深层诊断
```

- 空状态样式
- 错误状态样式
- 抽屉和详情页层级

## 最终判断

当前最值得先做的不是换颜色，而是：

> 修好工作台，然后把全站从“技术状态展示”改成“工作任务导航”。



## 会话工作台右侧辅助面板

> 检查来源：`RightPanel.tsx:11-112`、`WorkspaceView.tsx:321-434`、`ChangesPanel.tsx:11-36`，均位于 `packages/web-app/src/pages/workspace/`。文件布局另参考 `FileExplorer.tsx:25-28,223-226`。以下区分源码事实、推断与 mock 设计。

### 已确认事实

- 右栏只有三个标签：文件（`FileExplorer`）、产物（`ArtifactsPanel`）、改动（`ChangesPanel`）；源码明确说明不提供 Terminal 标签。
- 文件使用当前会话附件地址；产物还以 `sessionFile` 隔离。改动按读取来源（本会话工作区/子会话工作区）分组，不代表改动由哪个 Agent 或会话产生。
- `ChangesPanel` 明确不提供 diff：真实协议只有变更清单，不能用当前文件内容伪造差异。
- 改动项打开文件时通过 `fileOpenTargetOf` 请求文件工作流，并自动切回“文件”标签。
- 桌面端采用可调宽度的分栏；移动端为 300px 抽屉。右栏移动可见性绑定 `mobileNavOpen`，但遮罩调用 `setRightPanel(false)`，两者不是同一状态开关。
- 外层 `WorkspaceView` 仅在 `lg` 及以上显示展开按钮；源码明确右栏默认收起。
- `FileExplorer` 的 narrow 模式为目录树与预览上下分栏，而不是只有文件树。

### 问题与建议

- **问题（事实）**：三类内容都位于同一窄栏，文件树、产物列表、改动清单的层级由各子组件自行决定；`RightPanel` 只负责切换与身份传递。
- **推断**：当主区、左侧会话栏和右栏同时打开时，主对话宽度可能被压缩；建议默认按需打开右栏，并在窄屏提供明确的打开/收起入口。
- **推断**：改动项切回文件标签是正确的任务链路，但用户需要知道当前查看的是哪条会话的文件；建议在面板头部持续显示会话/Agent上下文。
- **推断**：移动可见性与关闭动作使用不同状态，可能导致左右栏互相影响或关闭不符合预期；需要对真实页面单独复现。本轮未修改生产状态逻辑。
- **建议**：保留 Files / Artifacts / Changes 三个真实领域，不新增 Terminal 等未实现功能；通过标签、明确空态和身份提示建立信息优先级。

### 未验证事项

- 未运行浏览器验证真实组件在 `mobileNavOpen`、`collapsed` 和无连接/无附件状态下的实际视觉尺寸。
- 未穷举各子组件的格式支持、编辑器操作、异步错误及加载状态；本轮不修改真实业务功能。
- 未实测真实分栏拖拽。

### 本轮 mock 对应设计

- 保留文件 / 产物 / 改动三标签；默认收起，桌面展开为第三栏，窄屏使用独立遮罩抽屉。
- 顶部始终展示示例 Agent、会话和工作区；切换 Agent 后不显示上一 Agent 的文件预览。
- 文件支持目录折叠与只读示例预览；产物支持本会话 Markdown 示例预览。
- 改动分本会话与子会话读取来源，点击文件后切到文件页并展示预览，明确不提供真实 diff/提交/回滚。
- 所有内容为固定示例，无真实文件访问或写操作；图片等其他产物格式、真实加载失败状态未在本 mock 中模拟。
