# Changelog

## [Unreleased]

### Added

- **Research mode**: `researchMode: "auto" | "none" | "encouraged" | "required"` (default `auto`). Open / architecture tasks get research guidance in worker+rewrite prompts, an optional/required `## sources` schema section (`claim | url | relevance`), soft quality penalties (required without URL → score cap 60; encouraged → −10), and synthesis preference for tool-backed external citations over memory claims. Narrow implementation tasks stay `none`.
- **Stage-test harness**: `bun packages/moa-extension/scripts/stage-test.ts` runs Discovery → Ask → Rewrite → Workers → Synthesis as `--stage all` or per-stage with `--from` artifacts under `tmp/moa-stage/`. Shared runners live in `src/stages.ts`; stdin UI in `src/stage-cli-ui.ts`.
- **Stage-test CLI unit coverage**: `parseStageTestArgs` / `validateStagePrerequisites` / `planStageSequence` live in `src/stage-test-cli.ts` with deterministic tests; prerequisites fail before creating a run directory or loading models.

### Fixed

- **Synthesis context contract**: synthesis now renders the real `tco.assumptions` list regardless of `askEnabled` and injects the TCO block exactly once.
- **Runtime settings resilience**: malformed or non-object `PI_MOA_SETTINGS_JSON` values now log a warning and fall back to file/default settings instead of blocking `/moa run`.
- **Soft-recover dual-channel**: freeform worker bodies still fill the primary section for display, but `softRecovered` keeps the contract hard-fail (score ≤30) and treats empty synthesized `open_questions` as unresolved — blocks fake `all_complete` convergence.
- **In-process "No model selected" on stale model ids**: default worker models updated to IDs that exist in the registry (`alibaba-coding-plan/qwen3.6-plus`, `alibaba-coding-plan/kimi-k2.5`); in-process engine returns a clear stderr when `createAgentSession` leaves `model` unset (typical cause: `moa.yml` pointing at removed `alibaba-coding-plan/deepseek-v4-*` / `kimi-k2.6`).
- **Freeform worker output hard-failed quality at ≤30**: when workers omit every required schema header (`## plan` / `## open_questions`) but still emit substance, the parser now soft-recovers (body → primary markdown section + empty other required sections) so scoring can judge content. Prompt example blocks added so rewrite/workers prefer exact headers.
- **TUI status bar (design §7.3)**: `ui.setStatus("moa", …)` now shows `Round N/M · asking question i/n · divergent OK · grounded OK · critical BLOCKED` during multi-round ask; cleared when the run finishes.
- **Ask actions are answer / skip / stop all**: per-round ask uses `ui.select` for the three actions instead of requiring the user to type `STOP`. Typed `STOP` in freeform input remains a fallback.
- **Multi-round: remove discovery/planning phase split** (align with `docs/moa-multi-round-design.md`): every round emits `plan` + `open_questions` under one schema. Round history only injects previous answers and already-asked questions — no more "Round 1 forbid plan / Round 2 forbid questions" which caused obedient workers to fail the quality check.
- **All-workers quality-drop is fail-loud**: when every worker is `qualityDropped`, synthesis is **not** spawned; result is `ok: false` with `stderr: "all workers quality-failed"` and `convergenceSignal: "quality_failed"`.
- **Cross-round question convergence**: `previousQuestionKeys` is threaded into `collectOpenQuestions`; repeating the same question no longer burns `maxRounds`.
- **Discovery `output_schema` actually reaches workers**: after Discovery, `buildPlan(..., outputSchema)` rebuilds worker prompts; rewrite prompt receives `{{output_schema}}`.
- **`dispatchLog` wired into archive**: `executePlan` returns per-round entries; `/moa run` passes them to `buildMoaArchiveEntries`.

### Added
- **Configurable worker execution mode** (`workerExecutionMode: "subprocess" | "in-process"`): new `MoaWorkerEngine` seam decouples worker execution from the subprocess path. Two adapters:
  - `SubprocessWorkerEngine`: wraps existing `spawnMoaWorker()` — no behavior change.
  - `InProcessWorkerEngine`: runs workers in-process via `createAgentSession()` with `SessionManager.inMemory()`. Lower memory footprint (shares Bun runtime), but intentionally conservative: no extension discovery, no MCP/LSP, read-only tools only (`read`/`search`/`find`/`web_search`/`ast_grep`/`ast_grep`), no Python warmup, best-effort timeout semantics.
- **Mode factory** (`src/worker-engine.ts`): `createWorkerEngine(mode, shared)` creates the correct adapter by config value. Executor no longer depends directly on `spawnMoaWorker()`.
- `/moa status` now shows the current execution mode with capability notes when set to `in-process`.
- **Default is `subprocess`** — fully backward compatible. `in-process` is opt-in via `PI_MOA_SETTINGS_JSON`, `moa.yml`, or programmatic `MoaSettings.workerExecutionMode`.
- **Out-of-process worker / synthesis execution (mirrors pi-fusion 0.8.0 `extensions/pi-fusion/fusion.ts:737-745`)**: every worker and the synthesis now run as a separate `omp --mode json -p --no-session --no-lsp` subprocess, with `PI_MOA_SUBAGENT=1` set in the worker env so the moa extension no-ops in the worker process (no recursive moa). The worker process writes no session log, so the main session JSONL never sees worker tool calls (`async-result` events) and the synthesis LLM cannot read them from cwd. New `packages/moa-extension/src/subprocess.ts` owns the spawn, JSONL parsing, signal forwarding, and temp-file cleanup.
- **Synthesis is now strictly tool-free**: the worker / synthesis spawn uses `--no-tools` (was `tools: ["__none__"]`, which was a no-op magic string) plus `--append-system-prompt @file` for the system prompt. No more accidental tool access in the synthesis LLM.
- **Heterogeneous default MOA models**: `DEFAULT_WORKER_SLOTS` now carries explicit `model` strings for all three workers (Qwen 3.5 Flash / DeepSeek V4 Pro / Kimi K2.6, three different model families for diversity > strength, per the Together MoA paper 2024), and `DEFAULT_SETTINGS.synthesisModel` is set to DeepSeek V4 Pro 202606 (the higher-order synthesis model). New exports `DEFAULT_WORKER_MODELS` and `DEFAULT_SYNTHESIS_MODEL` let users reference or override the defaults programmatically. Smoke-tested against the live `narwal-plan` and `alibaba-coding-plan` endpoints; all 4 models return 200 OK with `stopReason=stop`.
- **Config file support (`moa.yml` / `moa.yaml` / `moa.json`)**: persistent overrides via either a global config (`~/.omp/agent/moa.{yml,yaml,json}`) or a project config (`<git-root>/.omp/moa.{yml,yaml,json}`). New `src/moa-config.ts` resolves both, merges with project winning on conflict, and tolerates malformed YAML / unknown fields / unreadable files (logs a warning, returns empty overrides — never blocks the user's `/moa run`). The same `Partial<MoaSettings>` shape is supported as the existing `PI_MOA_SETTINGS_JSON` env var. Mirrors pi-fusion 0.8.0's `extensions/pi-fusion/presets.ts` locator pattern (simplified: no named presets, just a single layout override).
- **Discovery + Rewrite stages (TCO pipeline)**: `executor.ts` now runs a 5-stage pipeline — `discovery → ask-user → rewrite → workers → synthesis` — instead of the old 2-stage `workers + synthesis`. The new stages close the **Data Gap** (29.1% of multi-agent failures per AgentAsk ACL 2026) by injecting the user's task context, known facts, and explicit assumptions into every worker prompt.
  - **Discovery stage** (`prompts/discovery.md`): reads `~/.omp/agent/user.md`, `~/.omp/agent/moa.yml`, and cwd project files (README / package.json / Cargo.toml) as a pre-gathered context block, then runs a single LLM call to produce a **Task Context Object (TCO)** = `{ task_understanding, known_inputs[], missing_inputs[], assumptions[] }`. The contract is **generated per-task by the LLM**, not hardcoded per role. Bounded to 5 missing inputs.
  - **Ask-user stage** (`src/ask-user.ts`): for each missing input, calls `ctx.ui.input()` / `ctx.ui.select()` sequentially. TUI mode (`ctx.hasUI === true`): 30s per-question timeout. Gateway / cron: skips the ask, records every missing input as `[assumed: non_interactive_fallback]`. User-skip on a required input is recorded as `[assumed: user_skipped_required]` and surfaced by synthesis.
  - **Rewrite stage** (`prompts/rewrite.md`): takes the closed TCO and generates 3 role-specific worker prompts. When rewrite is disabled, the original `worker.md` template is used with the TCO prepended.
  - **TCO injection** (`src/tco.ts`): every worker and synthesis prompt is prepended with a bounded (`tcoInjectMaxBytes`, default 8KB) `## Task Context (from discovery stage)` block. The synthesis prompt gets an additional `## Assumptions to verify` block.
- **MoaTraceDetails now surfaces TCO summary** in the user-visible `moa-result`: known inputs, asked questions (with `*` for required), and assumptions (with reason). Full TCO is persisted in the `moa-archive` chunks for `/moa transcript`.
- **MoaArchive now includes Discovery + Rewrite sections** plus a TCO JSON block. The archive is the durable audit trail; the visible handoff is bounded.
- **PR1 of multi-round design (`docs/moa-multi-round-design.md`)**:
  - **Dynamic output schema** (`MoaOutputSchema` / `DEFAULT_OUTPUT_SCHEMA` in `src/types.ts`): per-task description of the sections a worker output must contain. Discovery LLM generates one in PR2; PR1 uses the hardcoded default `plan` / `open_questions` / `assumptions` shape.
  - **Worker output contract parser + quality heuristic** (`src/worker-parser.ts`): pure functions `parseWorkerOutputBySchema`, `scoreWorkerOutput`, `applyWorkerParsing`. Parses `## <name>` sections case-insensitively, scores 0-100, force-drops workers that miss any required section (score capped at 30). PR2 wires the call from executor.
  - **`MoaWorkerResult` extended** with optional `parsed: Record<string, string>`, `qualityScore?: number`, `qualityDropped?: boolean`, `parsedAt?: string`. All backward-compatible — existing callers see no change.
  - **`MoaDispatchLogEntry` type** added (`src/types.ts`); `MoaArchiveManifest.dispatchLog?` field added in `src/trace.ts`. PR1 ships the type and the manifest writer; PR2's multi-round executor populates it. `buildDispatchLogFromResults()` helper builds round=1 entries from existing worker results.
  - **TCO `defaultValue` flow** (`src/tco.ts` + `src/ask-user.ts`): Discovery LLM can now suggest a per-question `defaultValue`. When the user skips a question (or in non-interactive mode), the resulting `TcoAssumption.value` inherits that default instead of the previous type-empty fallback (e.g. `[]` for list, `false` for confirm). Fixes the long-standing "Discovery LLM gives an empty list, worker has nothing to plan around" failure mode.
  - **Worker prompt rewrite** (`src/prompts/worker.md`): top-of-file `## Hard rules (non-negotiable)` block (1. no clarifying questions in prose, 2. use `[assumed: ...]` as working assumptions, 3. one angle only, 4. follow the schema exactly). New `## Required output schema` section rendered from `MoaOutputSchema` via `planner.ts:renderOutputSchemaAsMarkdown`. Reminders updated to be schema-agnostic so they work with any custom schema.
  - **Rewrite prompt updated** (`src/prompts/rewrite.md`): rewrite LLM is now explicitly told to embed the `## Hard rules` and `## Required output schema` blocks verbatim in every generated worker prompt. The dynamic contract propagates through rewrite.
  - **Synthesis prompt updated** (`src/prompts/synthesis.md`): no-clarifying-questions hard rule moved to top; workers' `## open_questions` and `## assumptions` sections are now first-class reading targets (not buried in `### Unknowns / assumptions`).
  - **Discovery prompt updated** (`src/prompts/discovery.md`): Discovery LLM is now told to also output an `output_schema` block alongside the existing TCO JSON. PR1 writes the instruction but does not read it; PR2 enables the read path.
  - **Planner signature** (`src/planner.ts`): `buildPlan` now accepts an optional `outputSchema: MoaOutputSchema` (defaults to `DEFAULT_OUTPUT_SCHEMA`). Worker prompts get the schema rendered into the `## Required output schema` section.
- **PR2 of multi-round design (`docs/moa-multi-round-design.md`)**:
  - **Multi-round executor loop** (`src/executor.ts`): `executePlan` wraps workers in a bounded loop when Round-Ask is enabled. Gateway/cron (`hasUI=false`) force effective rounds to 0 (byte-identical to single-round). Each enabled round: fan out workers, parse + score, dedup open_questions, ask top-N via `askQuestionsList`, inject answers into TCO. Synthesis runs once with the last round's survivors.
  - **Quality heuristic drives the drop** (`DEFAULT_QUALITY_MIN_SCORE=40`): if a worker misses any required schema section, `scoreWorkerOutput` caps the score at 30 and `applyWorkerParsing` marks `qualityDropped=true`. 3-of-3 dropped ⇒ **fail loud** (no synthesis spawn; `stderr: "all workers quality-failed"`). 0-2 surviving ⇒ synthesis gets partial input.
  - **Dynamic schema is now read from Discovery** (`src/tco.ts`): `parseDiscoveryOutput` returns `{ tco, outputSchema }`. Falls back to `DEFAULT_OUTPUT_SCHEMA` when Discovery's payload is missing, empty, or malformed. `normalizeOutputSchema` helper is exported for tests.
  - **Per-round ask with STOP sentinel** (`src/ask-user.ts`): new `askQuestionsList()` accepts `AskQuestionsListItem[]` (key, question, type: freeform|choice, context, suggested_default, options, sourceWorkers). User types `STOP` to abort the loop — `result.stopped=true` propagates, the current round's `convergenceSignal` becomes `user_stop`, and synthesis runs with whatever we have. Non-TUI mode short-circuits to all-skipped with `reason: "non_interactive_fallback"`.
  - **Convergence signals** (`pickConvergenceSignal` in `src/executor.ts`): priority order `all_complete > user_stop > max_rounds > no_new_questions > null`. `all_complete` wins over `max_rounds` so a clean single-round TUI run is reported as "converged" rather than "budget exhausted". `no_new_questions` fires when the round's collected questions are empty AND not all complete.
  - **Settings** (`src/settings.ts`): `maxRounds` (plan-round budget; default later locked to 1 in once-right P1), `maxQuestionsPerRound=5`, `qualityMinScore=40`. `resolveSettings` clamps to non-negative ints / `[0, 100]`. Gateway/cron force effective rounds to 0 when `hasUI=false`. *(Once-right P1: Round-Ask is further gated by `postWorkerAskEnabled`, default false.)*
  - **New types** (`src/types.ts`): `MoaRoundTrace`, `MoaRoundQuestion`, `MoaConvergenceSignal`, `MoaRoundWorker`. `MoaExecutionResult` gained `rounds?: MoaRoundTrace[]` and `askRoundSummaries?: MoaAskUserSummary[]`. `MoaWorkerResult` gained `durationMs?` and `round?` for archive alignment.
  - **PR2 regex bug fix** (`src/worker-parser.ts` `SECTION_RE`): the trailing `\s*` between section name and `\n` was greedy and consumed the blank line between two consecutive sections (`## foo\n\n## bar`), making the body of `foo` swallow the `## bar` header. Switched to non-greedy `\s*?` and loosened the lookahead to `(?=\n##\s+|$)`. Regression test in `test/worker-parser.test.ts`.
  - **Trace wiring** (`src/trace.ts`): `buildDispatchLogFromResults` and `renderDispatchLogSection` from PR1 now correctly receive multi-round workers; `MoaArchiveManifest.dispatchLog?` carries per-round entries (round=1 for single-round, round=N for multi-round, with `qualityScore`/`qualityDropped` propagated).
  - **Test surface** (`test/`): 8 new test files / 60+ new assertions covering `askQuestionsList` (answer / skip / STOP / non-interactive fallback / choice), `normalizeOutputSchema` (missing / empty / dedupe / unknown type fallback), `parseDiscoveryOutput` schema read path, `resolveSettings` clamping, and a 6-case `moa executePlan — PR2 multi-round` describe block (single-round fallback, multi-round user-STOP, multi-round `all_complete` convergence, multi-round `max_rounds`, all-3 quality-dropped resilience, `maxRounds=0` defensive).

### Changed
- `executePlan` no longer takes a `runSubprocess` parameter. The old in-process `runSubprocess` from `@oh-my-pi/pi-coding-agent` is no longer used for moa workers or synthesis; `executor.ts` now calls `spawnMoaWorker` from the new `subprocess.ts`. The `agent`-shaped options object is replaced by a flat `SpawnWorkerInput`.
- `WorkerOutput` is the new return type: `{ ok, output, stderr, exitCode, aborted, timedOut, model, stopReason, usage, durationMs }`. The `moaWorkerResult.name` field is now sourced from the planner's worker name (was the agent name from `runSubprocess`).
- Tests now mock `subprocess.spawnMoaWorker` instead of `codingAgent.runSubprocess`. The `Omit<RegisteredCommand, "name">` test stub is unchanged structurally; only the mock target moves.
- `normalizeWorkerSlots` now falls back to the default `model` and `thinking` fields when a user override omits them, so changing only the worker's name/role no longer strips the default model binding.
- `executePlan` options now include optional `ui: ExtensionUIContext` and `hasUI: boolean` so the new ask-user stage can reach the TUI. `handleRun` in `extension.ts` forwards `ctx.ui` + `ctx.hasUI` automatically. When `hasUI=false` (gateway / cron / batch), the ask-user stage records every missing input as `[assumed: non_interactive_fallback]`.
- The `MoaPlan.discoveryPrompt` / `MoaPlan.rewritePrompt` fields are gone; those stages render their own templates at execution time with the TCO injected.
- `MoaPlanWorker` gained `rewrittenPrompt?: string` so the archive can show what rewrite produced vs the original template.

### Fixed
- **Self-reference / recursive moa defense**: previously the synthesis LLM in the main process could read `cwd` and the session log to find prior worker intermediate state (`async-result` events), which produced a self-referential loop (see session `165312__aa9301b4.jsonl`). With out-of-process workers that have no session log, the main session only contains the bounded `moa-result` + `moa-archive` entries. The synthesis LLM no longer has access to worker intermediate state in the cwd.
- **MOA without model configuration collapsed to a single model** (the previous `resolveModel` fallback used `modelRegistry.getAvailable()[0]` for all four calls, defeating the entire heterogeneous-MOA premise). The new `DEFAULT_WORKER_SLOTS` and `DEFAULT_SETTINGS.synthesisModel` carry explicit per-role model strings, so three different worker models and a fourth synthesis model are used out of the box.
- **Project config path was `.pi/moa.yml` (pi-fusion convention) instead of `.omp/moa.yml` (OMP convention)**. The loader now looks at `<git-root>/.omp/moa.{yml,yaml,json}`, which is the OMP project state directory (sibling of `skills/`, `evolution/`, `cache/`, `behavior-check/`). The user-level path `~/.omp/agent/moa.{yml,yaml,json}` is unchanged.
- **2-of-3 workers blocked on clarifying questions for ambiguous tasks** (e.g. "design a 4-week hiring plan, 10 jobs, 3 tradeoff axes"): the grounded + critical models asked 4-5 questions and stopped, producing no plan. The new Discovery + Ask-user + Rewrite pipeline forces all 3 workers to proceed with explicit `[assumed: ...]` markers, so even when the user skips the ask, the workers get a closed TCO and produce full plans. Synthesis surfaces the assumptions so the user can correct them in a follow-up.
- **In-process worker ignored the read-only contract** (`src/worker-engine.ts:InProcessWorkerEngine`): the previous implementation declared `IN_PROCESS_TOOLS = ["read", "search", "find", "web_search", "ast_grep"]` but never applied it. When `input.tools === "all"` (the default for workers), `toolNames` was `undefined` and `createAgentSession` fell back to the full default set including `bash` / `write` / `edit` / `task`. The `/moa status` "in-process: read-only tools only" note was a contract that did not hold. `InProcessWorkerEngine.execute()` now forces `toolNames` to `IN_PROCESS_TOOLS` for non-`none` modes, and to `[]` (with `runEphemeralTurn` instead of the full agent loop) for `tools: "none"`. A worker plan that needs `bash` / `write` must use the subprocess mode; in-process is now an honest read-only fallback. Test coverage: `test/worker-engine-internal.test.ts` "read-only tool enforcement" describe block.
- **In-process usage only recorded the last assistant message** (`WorkerOutput.usage.turns` was hardcoded to `1`): multi-turn workers (read → plan → edit, etc.) under-reported `input` / `output` / `cacheRead` / `cacheWrite` / `cost` / `turns` in `MoaTraceDetails`, making cost attribution wrong. The new engine subscribes to the agent's `message_end` events and accumulates usage across the full run, mirroring `runSubprocess`. `agent_end` is used for final text fallback only, not for usage (mirrors the swarm executor's split to avoid double-counting when both events fire for the same message).
- **In-process `session.dispose()` had no timeout** (`src/worker-engine.ts:finally`): a worker stuck in cleanup (e.g. lingering subprocess pipe) could hang the whole moa run indefinitely. The new engine wraps `dispose()` in `untilAborted(AbortSignal.timeout(5000), ...)` so cleanup is bounded to 5s, same as the swarm `runSubprocess` contract.
- **In-process did not call `session.waitForIdle()` after `session.prompt()`**: the last-message extraction could race the agent loop's final turn, occasionally reading a stale message. The new engine awaits `waitForIdle()` after `prompt()` so trailing `message_end` / `agent_end` events are guaranteed to have fired.
- **In-process did not propagate session metadata** (`createAgentSession` was called without `parentTaskPrefix` / `taskDepth` / `agentDisplayName` / `attribution`): the worker's `AgentRegistry` entry was always the main agent, masking subagent topology in `/moa transcript` and gateway telemetry. The new engine passes `parentTaskPrefix: "moa-worker"`, `taskDepth: 1`, `agentDisplayName: "moa-worker"`, and `attribution: "agent"` on `session.prompt()`.
- **In-process `exitCode` was always `0` for any successful return** even when the assistant's `stopReason` was `"error"` or `"aborted"`: callers (e.g. `MoaTraceDetails`, the renderer) treated a transport error as a clean run. The new engine maps `stopReason === "error" | "aborted"` to `exitCode: 1` and surfaces `errorMessage` as `stderr`, matching the subprocess contract.
- **Worker prompt rule 1 was ambiguous** (`src/prompts/worker.md`): the old text said *"Do not call any user-facing tool"* and left "user-facing" to LLM inference. Since the in-process engine makes 4 read-only tools (`read` / `search` / `find` / `web_search`) available, the LLM had to guess whether those count as "user-facing" — and in subprocess mode the LLM receives the full default tool set (bash / write / edit / task / yield / ...), making the inference burden much higher. Rule 1 is now an explicit **allow** + **forbid** list (with the principle: "read-only data gathering only") so the prompt-level contract matches the code-level `IN_PROCESS_TOOLS` (in-process) and the orchestrator's policy intent (subprocess). `src/prompts/rewrite.md` was updated in lockstep: the rewrite stage now has a `## Reference: Worker hard rules` block (the full rule 1–4 text) and step 3 explicitly forbids the rewrite LLM from weakening or omitting the tool policy when generating per-worker prompts.
- **In-process ephemeral stages reported 0 usage** (`src/worker-engine.ts` `runEphemeralTurn` branch): `runEphemeralTurn` is a side-channel LLM call that does not emit `message_end` events, so the previous code only called `recordAssistant` (for text extraction) and skipped `accumulateUsage`. Discovery / rewrite / synthesis all use `tools: "none"` and go through this path, so their `WorkerOutput.usage.input / output / cacheRead / cacheWrite / cost / turns` were always `0` — silently breaking cost attribution in `MoaTraceDetails` (4 LLM calls per moa run, 0 reported). The fix calls `accumulateUsage(ephemeralMessage)` right after `recordAssistant` in the ephemeral branch; no double-count risk because ephemeral produces exactly one assistant message. Test coverage: 3 new cases in `test/worker-engine-internal.test.ts` "ephemeral path" describe block — usage accumulation, text extraction, and `stopReason="error"` exitCode mapping.

### Notes (in-process mode, Alt 3b scope)
- **Settings isolation is intentionally NOT implemented** in this pass. The swarm `runSubprocess` isolates via `createSubagentSettings` (snapshot + `async.enabled=false` + `bash.autoBackground.enabled=false`). The moa in-process engine has no code path to mutate settings — `disableExtensionDiscovery: true` + `IN_PROCESS_TOOLS` (no `bash` / `python` / `task` / `async` access) means there is no worker action that can change parent settings. If `IN_PROCESS_TOOLS` is ever expanded to include side-effect tools, revisit and import the schema to do a full snapshot.
- **Recursion gating is structurally impossible, not enforced.** `IN_PROCESS_TOOLS` does not include `task`, so a worker cannot spawn a sub-agent. The depth check is therefore a no-op in in-process mode; the executor's `taskDepth: 1` is still passed for telemetry. If `IN_PROCESS_TOOLS` is expanded, re-introduce the `maxRecursionDepth` gate from `runSubprocess` (`packages/coding-agent/src/task/executor.ts:517-520`).

- The `MOA_OMP_BIN` env var allows the user / test harness to override the OMP binary used to spawn workers. Default: `Bun.which("omp")` → `omp`. This is mostly relevant for dev runs that want `bun --cwd=packages/coding-agent src/cli.ts` instead of a compiled `omp`.
- Workers are now stateless: they get the system prompt via `--append-system-prompt @file` and the task via the positional `@file` arg, matching pi-fusion's `buildWorkerArgs`. The user's full agent definition is NOT used by the worker; only the moa planner's per-worker prompt.
