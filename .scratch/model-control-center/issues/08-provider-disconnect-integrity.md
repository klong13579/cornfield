# 08: 保护 Provider 断开与配置完整性

**What to build:** 用户断开 Provider 前能看到它对当前会话、角色主模型和回退链的完整影响，并优先完成替换。强制断开需要二次确认，且系统必须保留“配置已经失效”这一事实，不得静默改用其他模型。完成该切片后，模型控制中心的旧页面和旧交互被清理，只剩一致的新设计。

**Blocked by:** 03: 通过 Web 完成 Provider 接入；06: 迁移到角色级模型路由；07: 交付原子化角色配置编辑器

**Status:** ready-for-agent

- [ ] 断开前列出当前会话、角色主模型和每一级回退链依赖
- [ ] 默认流程引导用户为所有依赖选择替代模型后再断开
- [ ] 强制断开需要展示具体影响并进行二次确认
- [ ] 强制断开不静默修改任何角色配置或当前会话模型
- [ ] 受影响配置明确进入“失效待修复”状态，并出现在控制中心顶部异常区
- [ ] 重新接入 Provider 后，仍存在的原配置可重新变为有效，不需要猜测性重建
- [ ] 并发配置修改、当前会话正在调用、OAuth 失效和本地端点离线等竞态有明确处理
- [ ] 完成模型目录、Provider、作用域、角色路由、刷新、测试和断开保护的全链路验证
- [ ] 删除旧模型市场页面的伪最新筛选、静默错误路径和已被新控制中心替代的交互
- [ ] 提交前通过变更影响检测确认受影响流程符合预期
